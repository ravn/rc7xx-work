**Rule:** when work has reached a clean checkpoint where resuming in
a new session would be cleaner than pushing on in the current one,
state exactly:

> This is a good place to start a new session.

Verbatim. No preamble, no rationale, no soft-pedalling. Stop after
that line.

**What NOT to say:**
- "at this hour"
- "the session has been running a while"
- "this benefits from a clean head" / "fresh context"
- "you might want to pick this up tomorrow"
- "given how long we've been working"
- any reference to wall-clock time, fatigue, or session length

**Why:** session 2026-06-12. I kept hedging the recommendation to
stop with phrases like "at this hour", "benefits from a fresh head",
"don't blast through". User: *"You do not have to nudge me to start
a new session referring to hour of day, or long sessions. Just state
'This is a good place to start a new session' when applicable."*

The hedging adds noise and presumes things about the user's state
(tired, end-of-day) that aren't mine to assert. The judgment of
"this is a checkpoint" is useful; the editorial frame around it
isn't.

**How to apply:**

1. When the work has reached a checkpoint AND continuing would
   benefit from a clean context restart (design ambiguity resolved
   but unwritten, large refactor at the start, etc.), state the
   verbatim line and stop.
2. When the work has reached a checkpoint but continuing is fine,
   don't say anything — just continue or summarize as normal.
3. When the work is mid-flight and incomplete, definitely don't say
   it — finish what you started.
4. Pre-line summarizing of the checkpoint's state (what's landed,
   what's open) is fine — that's useful handoff content. The line
   itself goes at the end with no commentary.
