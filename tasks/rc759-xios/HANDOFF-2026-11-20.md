## Seneste arbejde: BDOS dispatch-tabel-dump (UAFSLUTTET)

**Motivation**: De statiske dispatch-tabeller i ccpm.sys er nul (patches af GENSYS ved boot). MAME-trace kan læse dem ved runtime. Med adresserne kan vi navngive alle BDOS-funktioner ved at matche DRI-kildekodens funktionssignaturer.

**Hvad der skete:**

Kørte `scratch/tmp/bdos_dispatch_dump.lua` via MAME ved t=301s (CCPM fuldt bootet). Scriptet returnerede data, men **dataene er forkerte** — det læste ASCII-tekst i stedet for dispatch-pointere:

```
MOD1 fn00: 0x432D   ← bytes 2D 43 = '-' 'C'
MOD1 fn01: 0x6D6F   ← bytes 6F 6D = 'o' 'm'
MOD1 fn02: 0x7570   ← bytes 70 75 = 'p' 'u'
MOD1 fn03: 0x6574   ← bytes 74 65 = 't' 'e'
MOD1 fn04: 0x2072   ← bytes 72 20 = 'r' ' '
...                 ← "Computer Denmark ..."
```

**Årsag**: Scriptet antog `CS_BASE = 0x0480` (paragraph 0x0048 = load-adressen for hele ccpm.sys). Men BDOS-modulerne (modul 1-3) har **egne CS-segmentregistre** der sættes af MEMIF-loaderen ved boot — de er IKKE ved 0x0480.

## Hvad der mangler: Korrekt CS for BDOS-modulerne

### Loader-model (fra fase 0.2)

ccpm.sys loades ved paragraph **0x0048** (physical 0x0480). Fil-offsets for modulerne:

| Modul | Fil-range (offset) | Størrelse | Indhold |
|-------|-------------------|-----------|---------|
| 0 (RTM) | 0x00080–0x0163F | 5568 B | RTM-kerne |
| 1 (BDOS1) | 0x01640–0x026BF | 4224 B | Fil-system del 1 |
| 2 (BDOS2) | 0x026C0–0x031DF | 2848 B | Fil-system del 2 + konsol |
| 3 (BDOS3) | 0x031E0–0x03ACF | 2288 B | Konsol-I/O manager |
| 4 (XIOS) | 0x03AD0–0x12EFF | 62512 B | XIOS + SYSDAT |

Hvis modulerne loades som **flade segmenter** fra filen:
- Modul 0 starter ved file-offset 0x0080 → physical `0x0480 + 0x0080 = 0x0500` → paragraph **0x0050**
- Modul 1 starter ved file-offset 0x1640 → physical `0x0480 + 0x1640 = 0x1AC0` → paragraph **0x01AC**
- Modul 2: `0x0480 + 0x26C0 = 0x2B40` → paragraph **0x02B4**
- Modul 3: `0x0480 + 0x31E0 = 0x3660` → paragraph **0x0366**

**MEN**: MEMIF kan re-allokere moduler, og der er en 0x80-byte fil-header der ikke loades. Den korrekte CS kan afvige.

### Anbefalede tilgange til at finde den korrekte CS

**Tilgang A — Beregn fra fil-offset (nemmest at prøve):**

Korrigér scriptet: Modul 1 (BDOS1) CS ≈ paragraph 0x01AC (physical 0x1AC0).
Dispatch-tabel MOD1 ved CS:0x006C → physical `0x1AC0 + 0x006C = 0x1B2C`.

```lua
-- Prøv disse CS-baser i stedet for 0x0480:
local MOD0_CS = 0x0500   -- RTM
local MOD1_CS = 0x1AC0   -- BDOS1  ← dispatch ved CS:0x006C
local MOD2_CS = 0x2B40   -- BDOS2
local MOD3_CS = 0x3660   -- BDOS3  ← dispatch ved CS:0x004C
```

**Tilgang B — Læs MEMIF module-descriptor-tabel ved runtime:**

RTM har en tabel over aktive modulers CS/DS-værdier. Dens adresse er sandsynligvis i SYSDAT eller ved et fast RTM-offset. Se `tools/rtm_svc_trace.lua` for arbejdende MAME-teknik.

**Tilgang C — Sæt breakpoint på dispatch-kald:**

`call cs:[si + 0x6C]` i MOD1 er ved fil-offset ca. 0x17xx. MAME Lua kan sætte en watchpoint/breakpoint ved den fysiske adresse og logge CS+SI+[SI+0x6C] ved hvert kald.

## Vigtige tekniske facts (huskeliste)

**MAME-regler (HARD RULE fra CLAUDE.md)**:
- Kald ALDRIG `mame`, `regnecentralen`, `regnecentralend` direkte fra shell
- Brug kun Makefile-targets eller wrapper-script `rc700-gensmedet/scripts/mame_capture.sh`
- Hvis der ikke er et passende Makefile-target, skriv et nyt wrapper-script

**Fungerende MAME Lua-mønster** (fra `tools/rtm_svc_trace.lua`):
```lua
_f = io.open(OUT, "a")          -- globale vars (_f, _ref) forhindrer GC
_ref = emu.register_frame_done(function()
    local t = manager.machine.time.seconds
    if t > 4 and t < 5 then
        pcall(function() manager.machine.natkeyboard:post("A\n") end)
    end
    -- ... læs memory ved t > 300
    local mem = manager.machine.devices[":maincpu"].spaces["program"]
    local val = mem:read_u16(phys_addr)
end)
```

**CCPM.SYS arkitektur:**
- 5 MEMIF-moduler, loades ved paragraph 0x0048 (physical 0x0480)
- SYSDAT segment: DS=0x06FA, physical 0x06FA0, fil-offset 0x06B20
- RTM service-tabel: SYSDAT+0xAA = physical 0x704A
- Inter-modul kode-format: `0xMMFF` = modul×0x100 + funktionsnummer
- GENSYS patcher dispatch-tabellerne ved boot (statisk binær har dem som nuller)

**BDOS dispatch-pointer:**
- MOD1 bruger `call cs:[si + 0x6C]` (dispatch-tabel ved CS:0x006C)
- MOD3 bruger `call cs:[si + 0x4C]` (dispatch-tabel ved CS:0x004C)
