## 1. Projektets Formål & Status

Reverse engineering af styresystemet **Concurrent CP/M-86 3.1** (`ccpm.sys`, 77.568 bytes) for **Regnecentralen RC759 Piccoline** (dansk 80186-baseret skolecomputer, 1984–1989).
Målet er en 100% byte-for-byte verificeret NASM-genskabelse, fuld modularisering, opmærkning af alle hardware-drivere og arkitektonisk forståelse.

### Status lige nu
- **Reassembly**: **100% byte-for-byte identisk (77.568 bytes)** mod referencefilen `scratch/tmp/ccpm.sys`.
- **Verifikationsscript**: `./tasks/rc759-xios/rebuild_and_verify.sh` (afvikles i Docker-containeren `rc759-nasm`).
- **Modularisering**: Koden er fuldstændig opdelt i 5 operativsystemmoduler plus 5 selvstændige Resident System Processes (RSP), samlet via master-filen [tasks/rc759-xios/ccpm.asm](file:///Users/ravn/z80/tasks/rc759-xios/ccpm.asm).
- **Branch**: `main`.
- **Regler**: Følg altid `AGENTS.md` (aldrig push eller åbn PR uden eksplicit ordre i DENNE tur, ingen @-mentions af tredjeparter, verificér altid binær lighed før "done").

## 3. Dokumentation og Nøgleresultater etableret i denne session

Alle fund er grundigt dokumenteret i dedikerede markdown-filer i `tasks/rc759-xios/` og `tasks/memory/`:

1. **INT 28H Extended XIOS / BIOS Interface (54 funktioner, 0..53)**:
   - [int28h_functions_map.md](file:///Users/ravn/z80/tasks/rc759-xios/int28h_functions_map.md) & [reference_rc759_int28h_xios_api.md](file:///Users/ravn/z80/tasks/memory/reference_rc759_int28h_xios_api.md).
   - Omfatter grafikskift (Fn 0/1), blød rulning (Fn 2), font-RAM (Fn 20/51/52), 82730 displaylister (Fn 21/22), NVRAM (Fn 3), Autokonfiguration (Fn 4), direkte floppy track-I/O (Fn 5/8/9/10/11/13), SN76489 lydchip (Fn 12), 16 ms timer (Fn 19), iSBX 351 (Fn 23/24/50), båndoptager (Fn 26-29/40), mus (Fn 30) og version (Fn 53).
   - Dispatcher ved `0x07831` kalder `int28h_jump_table` ved `0x0784C` (`CS:0CAC`, 54 words).
   - Segmentbasis er `xios_code_base = 0x06BA0`. Alle 54 funktioner er forsynet med `xios_int28_fn_...` labels i `mod4_xios.asm`.
2. **NVRAM / NVM Komplet Specifikation (128 bytes)**:
   - [nvram_map.md](file:///Users/ravn/z80/tasks/rc759-xios/nvram_map.md) & [reference_rc759_nvram_map.md](file:///Users/ravn/z80/tasks/memory/reference_rc759_nvram_map.md).
   - Checksum: $\sum_{i=0}^{95} \text{byte}[i] \pmod{256} = \text{0xAA}$.
   - Kritiske bytes: `0x12` (scroll mode), `0x35` (maskin-ID: `0xFF` = Piccoline, `0x00` = Partner), `0x0D` (iSBX 351 baudrate = 9600), `0x14` (floppymotor timeout = 5s), `0x16` (forgrundsfarve), `0x1B` (M-disk størrelse).
3. **Skærmarkitektur & Forskelle: Piccoline vs. Partner**:
   - [screen_architecture_piccoline_vs_partner.md](file:///Users/ravn/z80/tasks/rc759-xios/screen_architecture_piccoline_vs_partner.md) & [reference_rc759_screen_architecture_piccoline_vs_partner.md](file:///Users/ravn/z80/tasks/memory/reference_rc759_screen_architecture_piccoline_vs_partner.md).
   - **Skærm-RAM**: Piccoline bruger 32 KB dedikeret CRT-RAM uden for system-RAM (0 KB reservation i CCP/M RAM) via 82730; Partner bruger Motorola 6845 og stjæler de øverste 24 KB af system-RAM til frame-buffer.
   - **Interrupter**: Partner bevarer INT 1, INT 3 og INT 0xE1 for ROM-debuggeren; Piccoline overtager selv INT 3.
   - **Dynamisk detektion**: XIOS tjekker Auto-Configuration Map (`0000:0050` / `SYSDAT:4225`) offset 23: ASCII `'P'` = Partner, andet = Piccoline.
4. **Blød vs. Hård Rulning**:
   - CCB flag `[bx + 0x71]` og global standard `[cs:0x2c08]`.
   - `0` = Hård rulning (Line/Jump scroll): Opdaterer 82730 displayliste direkte.
   - `1` = Blød rulning (Soft scroll): Vækker `SCROLL.RSP` via Flag 4; `SCROLL.RSP` kalder `INT 28H, AL=2` scanline-step synkroniseret med VSYNC (Flag 9/10).
   - Toggles ved runtime via escape-koder `ESC <244>` (soft) og `ESC <245>` (hard).
5. **RSP Procesmodel i CCP/M-86**:
   - [reference_ccpm86_rsp_process_model.md](file:///Users/ravn/z80/tasks/memory/reference_ccpm86_rsp_process_model.md) & [distribution_sw1400.md](file:///Users/ravn/z80/tasks/rc759-xios/distribution_sw1400.md).
   - RSPs har **ingen relokeringstabel** (Gruppe 7 i CMD header er 0). De kører 8080-modellen (`CS=DS=ES=SS`) med relative spring.
   - `GENCCPM` placerer **Data Group først** (`RSPHDR` + `PD` + `UDA`) og **Code Group bagefter**.
6. **Målbinærens identitet**:
   - `ccpm.sys` er 100% identisk med **`CCPM1.SYS`** fra SW1400 distributionen (1 virtuel konsol, ingen netværk, linket med `XIOS1.CON`).
   - 4-konsol modparten er `CCPM4.SYS` linket med `XIOS4.CON`.

## 4. Konkrete Næste Skridt for Fremtidige Sessioner

Når arbejdet genoptages, er følgende opgaver klar til udførelse:

### Opgave A: Symbolisering af `rsp_scroll.asm` (Hurtig gevinst)
- `rsp_scroll.asm` er kun 102 linjer kode.
- Dens logik er nu fuldstændig kortlagt: Den sover på Flag 4, kalder `INT 28H, AL=2` (scanline-step) og synkroniserer med Flag 9 og Flag 10 via BDOS kald 132 (`Flag Wait`) og 133 (`Flag Set`).
- Den kan let omskrives med fulde symbolske konstanter og forklarende kommentarer (ligesom `rsp_clock.asm`).

### Opgave B: Finjustering af RSP-grænser for `rsp_vout.asm` og `rsp_scroll.asm`
- Ligesom CLOCK fik sit Data Segment udskilt fra TMP, og PIN fik sit Data Segment foranstillet koden, bør VOUT og SCROLL have deres Data Segmenter placeret i starten af deres respektive filer:
  - `rsp_vout.asm`: Data Segment `0x12240`–`0x125DF` (928 B) + Code Segment `0x125E0`–`0x12D1F` (1.856 B).
  - `rsp_scroll.asm`: Data Segment `0x12D20`–`0x12E5F` (320 B) + Code Segment `0x12E60`–`0x12EFF` (112 B + 48 B trailer).
  - Husk altid at køre `./tasks/rc759-xios/rebuild_and_verify.sh` efter enhver grænsejustering.

### Opgave C: Symbolisering af de 48 standard XIOS-funktioner i `xios_jump_table`
- I [tasks/rc759-xios/mod4_xios.asm](file:///Users/ravn/z80/tasks/rc759-xios/mod4_xios.asm#L38) findes `xios_jump_table` ved `CS:004Dh` (`0x03B1D`, 144 bytes = 48 entries á 3 bytes: `dw offset, db flags`).
- Funktion 0–31 er standard DRI XIOS funktioner (`?init`, `?wboot`, `?const`, `?conin`, `?conout`, `?list`, `?auxout`, `?auxin`, `?home`, `?seldsk`, `?settrk`, `?setsec`, `?setdma`, `?read`, `?write`, `?listst`, `?sectrn`, `?setdmab`, `?getsegt`, `?alloc`, `?dealloc`, `?dskreset`, `?select`, `?conbrk`, `?poll`, `?flag`, `?tick`, `?timedate`, `?delay`, `?stop`, `?exit`, `?idle`).
- Mange af subroutines er allerede fundet og navngivet; de resterende kan forsynes med standard DRI navne jf. DRI CCP/M-86 System Guide.

### Opgave D: Kildekoderestaurering af `XIOS1.CON` og systemgenerering via `GENCCPM`
- Distributionsfilerne ligger udtrukket i `scratch/tmp/dist/`.
- `tasks/rc759-xios/tools/run_genccpm.py` og emu2 kan bruges til at bygge `ccpm.sys` fra rå moduler, hvilket vil give os den fulde originale byggepipeline tilbage.
