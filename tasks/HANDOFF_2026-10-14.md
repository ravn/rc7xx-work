## Key ABI finding (critical context)

**llvmz80's `__smallc` under z80-unknown-none-z88dk triple is L-to-R push order (sccz80 convention), NOT sdcccall(0)/R-to-L.**

Empirically verified: `callee(42, 99)` with `printf("%p %p", &a, &b)` shows `&a` at HIGHER address than `&b` → first arg deeper on stack → pushed first → L-to-R.

The `__Z88DK_R2L_CALLING_CONVENTION 1` define in `include/sys/compiler.h` only gates ZPROTO *_callee variants in headers, **not** actual compiler push order.

Three distinct Z80 conventions:
- `__smallc` on llvmz80 (= default for z88dk triple) = L-to-R, caller cleanup = sccz80 compat
- `__smallc __z88dk_callee` = L-to-R, callee cleanup
- `__sdcccall(0)` = R-to-L, caller cleanup = sdcc compat

z88dk's classic library has **two entries per function**:
- bare name (`qsort`, `strcpy`, …) = sccz80 L-to-R entries
- underscore (`_qsort`, `_strcpy`, …) = sdcc R-to-L entries

LLVM auto-prefixes C symbols with `_`, so `qsort(...)` in C normally → `_qsort` in asm → sdcc entry → **wrong for llvmz80**.

## How the three z88dk changes resolve this

1. **`include/sys/compiler.h`**: moved `#define __STDC_ABI_ONLY` out of the `__LLVMZ80` branch. Enables ZPROTO bridges for llvmz80 while non-llvmz80 clang-shaped frontends (IDE indexers, ez80-clang) keep neutering.

2. **`include/stdlib.h`**: `qsort` and `bsearch` get `__asm__("qsort")` / `__asm__("bsearch")` under `__LLVMZ80` to bypass LLVM's underscore prefix and route to the sccz80 L-to-R entries (`l_cmp_sccz80` thunk).

3. **`src/zcc/zcc.c`**:
   - Force `c_clib = "ixiy"` unconditionally for llvmz80 → uses `z80iy_crt0.lib` + `cpmixiy_clib.lib` which ship the IY-reserved `__z80_memset_builtin` / `__z80_memcpy_builtin` helpers that the Z80 backend emits for vector memory ops.
   - Add `-fno-builtin-*` flags for all string functions so clang's builtin lowering doesn't bypass ZPROTO `*_callee` redirects.
